# 입회서류보완 자동 안내 시스템

## 1. 문제 정의

### 현행 프로세스 (AS-IS)

```
카드사(롯데/BC)         고위드 백엔드          슬랙 채널              운영담당자              고객
     │                      │                    │                     │                   │
     │  서류보완 요청        │                    │                     │                   │
     │─────────────────────→│  알림 발송          │                     │                   │
     │                      │───────────────────→│                     │                   │
     │                      │                    │  확인 (수기)         │                   │
     │                      │                    │────────────────────→│                   │
     │                      │                    │                     │  이메일 작성 (수기)  │
     │                      │                    │                     │──────────────────→│
     │                      │                    │                     │                   │ 서류 준비
     │                      │                    │                     │  이메일 회신        │
     │                      │                    │                     │←──────────────────│
     │                      │                    │                     │  GAM 업로드 (수기)  │
     │  서류 재제출          │                    │                     │                   │
     │←─────────────────────│←───────────────────│←────────────────────│                   │
```

**병목 지점**:
- 운영담당자가 슬랙 확인 → 이메일 작성까지 **수시간~1일** 소요
- 이메일 본문을 매번 수기 작성 (보완 서류 목록, 안내 문구)
- 고객이 이메일 첨부파일로 회신 → 운영담당자가 다시 GAM에 수기 업로드
- 하루 여러 건 발생 시 누락 위험

### 목표 프로세스 (TO-BE)

```
카드사(롯데/BC)         고위드 백엔드          슬랙 채널          자동화 봇             고객

     │  서류보완 요청        │                    │                  │                   │
     │─────────────────────→│  알림 발송          │                  │                   │
     │                      │───────────────────→│  감지 (자동)      │                   │
     │                      │                    │─────────────────→│                   │
     │                      │                    │                  │  Drive 폴더 생성    │
     │                      │                    │                  │  안내 메일 발송      │
     │                      │                    │                  │─────────────────→│
     │                      │                    │  처리 완료 알림    │                   │
     │                      │                    │←─────────────────│                   │
     │                      │                    │                  │                   │ Drive에 업로드
     │                      │                    │  업로드 알림       │                   │
     │                      │                    │←─────────────────│←──────────────────│
```

**개선 효과**:
- 보완요청 → 고객 안내: **수시간 → 5분 이내**
- 운영담당자 개입: **건당 10~15분 → 0분** (모니터링만)
- 서류 수집: 이메일 첨부 → **Google Drive 직접 업로드**

## 3. 슬랙 메시지 파싱

### 입력 메시지 형태 (2026-02-22 실제 확인)

`bot-카드사-입회서류보완` (C057EMUTZQR) 채널의 봇 메시지 실제 포맷:

```
> *[롯데_입회서류 보완 알림]*
>
>  법인명: 주식회사 XXX
>  사업자번호: 123-45-67890
>  서류보완메모: 사실상지배자리스트 첨부 및 전산등록 요청
```

메모가 복수 항목인 경우 (멀티라인):

```
> *[롯데_입회서류 보완 알림]*
>
>  법인명: 주식회사 YYY
>  사업자번호: 420-87-02727
>  서류보완메모: 1. '24년 재무제표 전산등록후 재심사 요청
2. 사실상지배자리스트 첨부 및 전산등록 요청
```

- 봇 이름: `롯데 서류 보완 알리미`
- 채널 토픽에 BC도 명시되어 있으나, 확인 시점 기준 롯데 메시지만 확인됨
- BC 메시지는 `[BC_입회서류 보완 알림]` 형태로 추정

### 파싱 필드

| 필드 | 추출 방법 | 필수 | 용도 |
|------|----------|------|------|
| 카드사 | 헤더 정규식 `\[(.+)_입회서류\s*보완\s*알림\]` | O | 이메일 제목/본문 |
| 법인명 | 정규식 `법인명\s*[:：]\s*(.+)` | O | 이메일 제목/본문 |
| 사업자번호 | 정규식 `사업자번호\s*[:：]\s*([\d\-]+)` | O | 고객 식별, 이메일 조회 키 |
| 서류보완메모 | 멀티라인 파싱 (상태 기계 방식) | X | 이메일 본문 (카드사 요청 내용) |

> **참고**: 이메일 주소는 메시지에 포함되지 않음. 사업자번호를 키로 BigQuery에서 별도 조회.

### 고객 이메일 조회 (BigQuery)

슬랙 메시지에 고객 이메일이 포함되지 않으므로, 사업자번호를 키로 DW에서 조회:

1. 사업자번호에서 하이픈 제거 → `corp_id` (INT64)
2. `dw_dimension.user` 테이블에서 해당 `corp_id`의 활성 사용자 조회
3. 역할 우선순위: `슈퍼 관리자` > `카드 총괄관리자` > 기타 활성 사용자
4. `is_email_allowed = 1`, `is_deleted = false`, `status = 'ACTIVE'` 조건 필터

```sql
SELECT u.email, u.name, u.role
FROM `gowid-prd.dw_dimension.user` u
WHERE u.corp_id = {사업자번호(하이픈 제거)}
  AND u.is_deleted = false
  AND u.status = 'ACTIVE'
  AND u.is_email_allowed = 1
  AND ('슈퍼 관리자' IN UNNEST(u.role) OR '카드 총괄관리자' IN UNNEST(u.role))
ORDER BY
  CASE WHEN '슈퍼 관리자' IN UNNEST(u.role) THEN 0 ELSE 1 END,
  u.created_at ASC
LIMIT 1
```

## 5. Google Drive 서류 업로드

### 폴더 구조

```
[입회서류보완] (루트 공유 폴더)
└── {법인명}_{사업자번호}_{날짜}/
    └── (고객이 여기에 서류 업로드)
```

### 공유 설정

| 설정 | 값 | 이유 |
|------|-----|------|
| 접근 권한 | 링크가 있는 모든 사용자 (편집 가능) | 고객이 별도 로그인 없이 업로드 가능 |
| 폴더 소유자 | 고위드 운영 계정 | 서류 관리 주체 |
| 만료 | 없음 (수동 정리) | 고객 편의 우선 |

### 업로드 모니터링 (Phase 2)

- Google Drive API의 변경 감지(watch) 기능으로 새 파일 업로드 시 슬랙 알림
- 초기 프로토타입에서는 미구현, 운영 안정화 후 추가

```

• 수신자: admin@example.com
• 법인명: 주식회사 테스트
• 카드사: 롯데카드
• 보완 내용: 사실상지배자리스트 첨부 및 전산등록 요청
• Drive 폴더: [링크]
• 발송 시각: 2026-02-22 10:30
```

### 이메일 조회 실패 알림

BigQuery에서 고객 이메일을 찾을 수 없는 경우:

```
⚠️ 이메일 조회 실패 - 수기 처리 필요
• 법인: 주식회사 테스트
• 사업자번호: 123-45-67890
• 원인: BigQuery에서 해당 법인의 관리자 이메일을 찾을 수 없음
```

### 오류 알림

파싱 실패 또는 메일 발송 실패 시:

```
⚠️ 자동 처리 실패 - 수기 처리 필요
• 원인: {오류 메시지}
• 시각: 2026-02-22 10:30
• 조치: 이 메시지의 원본을 확인하고 수기로 고객에게 안내해 주세요.
```
